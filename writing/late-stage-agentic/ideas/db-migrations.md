# Миграции базы данных — единственное исключение

Параллельные ветки не дерутся, потому что git умеет мёрджить текст. С миграциями
ломается не мёрдж, а нумерация: две ветки одинаково назовут свою миграцию
`0080`, и сольются они без единого конфликта — коллизию видно только тогда, когда
их начинают применять. А если обе сессии смотрят в одну dev-базу, наступить друг
другу на ноги они успевают ещё до слияния. Тема нишевая, но это ровно то место,
где совет «запускайте десять сессий» перестаёт работать, — и честнее назвать его,
чем обойти.
