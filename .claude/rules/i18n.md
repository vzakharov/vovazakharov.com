# Translation

**Every locale is a page of its own, already rendered.** `/cv/cto/en` and
`/cv/cto/ru` are separate files in the static export, each carrying its own
language's text, and the language chips are plain `<a href>` — switching is a
navigation, not a re-render. So **nothing here translates in the browser**, and
next-intl's client runtime — 48 kB raw, 14 kB gzipped — is banned rather than
rationed.

Two guards hold that, deliberately overlapping:

- **`@typescript-eslint/no-restricted-imports` rejects the bare `next-intl`
  specifier**, which is the library's client entry — `useTranslations`,
  `useMessages`, `NextIntlClientProvider`. It catches the import where it is
  written, and it carries no exemptions, because there is no page it has to make
  room for. A type-only import is allowed: it costs no bytes.
- **`pnpm check:i18n-payload` reads the built pages** and fails on any that
  references a chunk carrying the runtime. It covers what a lint rule cannot
  see — a dependency pulling the runtime in transitively — because what a page
  costs is not a property of the file an import sits in.

**The locale is an address's last segment** — `/cv/cto/ru`, `/music/slime/ru` —
and an address with none is in the default language, an alias whose canonical
is the page with it. `locales.ts` holds the convention whole: `LocaleTail` and
`localeTailAddresses` for a route enumerating its addresses, `addressLocale` for
a client component above the page reading one back. A slice keeps only the
parse of the segments before the locale, whose shape only it knows. A layout's
server half cannot read the locale at all — it is never handed the segments
below it, and a static export has no request to ask — so what it renders in
the page's language goes through a client component, or both languages down.

## How to translate instead

**A server component reads the copy and passes strings down.** Two forms, by
whether the locale is the page's own:

- `getTranslations` from `next-intl/server` — the shell's form, where the locale
  is the default one. `ThemeCorner` awaits `getTranslations('ui')` and hands
  `ThemeToggle` its label as a prop.
- The catalogue itself, through `@/shared/i18n` — the CV's form, because its
  copy is `cvMessages(locale, variant)`: one locale's catalogue with the
  framing's overrides merged over it, a shape no request config can produce.
  `CvPage` resolves it and `CvSheet` reads it as a typed object, so every key is
  checked by `tsc` rather than by a message-key string.

**A catalogue holds markdown, never tags.** `**emphasis**` is the whole of what
a message may carry, and `MESSAGE_MARKDOWN` fails the render on anything else
rather than letting it reach a reader. Bullets carry their bold lead as
structured fields (`lead`, `label`) instead, so inline markup stays confined to
running prose.

**A client component that needs a translated string is a signal to move the
string up** to whoever renders it. What may cross into a client bundle from this
segment is `@.claude/rules/fsd.md`'s barrel split.

## Changing the decision

Lifting the ban means deciding that a page switches language **in place** —
without a navigation, as a page holding scroll position or form state would
need to. That is a product decision, not a refactor: it costs every page whose
graph reaches the runtime 14 kB, and it makes the per-locale pages redundant for
that route. Record it here first, then relax the lint rule — and the payload
check, being a backstop rather than a rationing scheme, would then need a
permitted set spelled out.
