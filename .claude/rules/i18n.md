# Translation

**The bare `next-intl` specifier is the library's client entry, and a page whose
graph reaches it ships that runtime — 48 kB raw, 14 kB gzipped.** A page that
renders in more than one language earns it; one that renders in a single
language pays for nothing. `pnpm check:i18n-payload` is what holds that, and it
derives the permitted set rather than listing it: a locale from
`routing.locales` appearing in a page's route or under it is what qualifies the
page, so **a new localized page needs no allowlist extended anywhere.**

**Everywhere else, a server component translates and passes the string down.**
`ThemeCorner` is the pattern: it awaits `getTranslations('ui')` and hands
`ThemeToggle` its label as a prop, so the one client component outside the CV
carries no translation machinery for the one string it renders. A component that
needs a translated string and cannot be a server component is a signal to move
the string up to whoever renders it.

**A key in `messages/*.json` does not earn a runtime.** The catalogues are read
on the server too, so copy for a page that renders in one language is a
`getTranslations` call in that page, prop-drilled as far as it has to go. What
may cross into a client bundle from this segment is `@.claude/rules/fsd.md`'s
barrel split.

## Why this is a build check and not a lint rule

A lint rule can only ask which file an import sits in, and that does not
separate the cases: a localized page translates on the client precisely so the
reader can switch language without a navigation, so **every legitimate caller of
`useTranslations` is a client component inside a localized page** — and the
nearest available discriminator is a hand-listed path glob, which is the thing
that goes stale the first time a second page is localized. The cost is a
property of a page, so the page is what gets measured.

`getTranslations` in a client component needs no guard: next-intl resolves
`next-intl/server` through the `react-server` export condition, so a client
bundle gets a stub whose every export throws when called. The mirrored mistake
is the quiet one — `useTranslations` in a client component **works**, and bills
that page silently.
