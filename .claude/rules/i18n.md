# Translation

**The bare `next-intl` specifier is the library's client entry, and a page whose
graph reaches it ships that runtime — 48 kB raw, 14 kB gzipped.** So it is
restricted to one subtree rather than available everywhere:
`@typescript-eslint/no-restricted-imports` blocks it repo-wide and
`eslint.config.ts` exempts `src/pages/cv/ui/**`. Type-only imports are allowed,
the objection being bytes rather than coupling.

**The CV earned the exemption by rendering in two languages with a switch
between them**, so it holds its own `NextIntlClientProvider` and its own
messages. Nothing else on the site re-renders in a second language after load,
which is what makes a runtime there a cost with no matching behaviour.

**Everywhere else, a server component translates and passes the string down.**
`ThemeCorner` is the pattern: it awaits `getTranslations('ui')` and hands
`ThemeToggle` its label as a prop, so the one client component outside the CV
carries no translation machinery for the one string it renders. A component that
needs a translated string and cannot be a server component is a signal to move
the string up to whoever renders it, not to widen the exemption.

**A key in `messages/*.json` does not earn a provider.** The catalogues are read
on the server too, so adding copy for a page outside the CV is a
`getTranslations` call in that page, prop-drilled as far as it has to go — and
`src/shared/i18n/index.ts` stays client-safe for exactly that reason, keeping
only `routing` and `loadMessages` while `localeSchema` sits behind
`index.server-only.ts` (zod is ~90 kB; `@.claude/rules/fsd.md` owns that split).

## `getTranslations` in a client component throws at call time

It is not a build error and not a type error. next-intl resolves
`next-intl/server` through the `react-server` export condition, so a client
bundle gets a stub whose every export throws "`getTranslations` is not supported
in Client Components" when called. The mirrored mistake is the quiet one, and
the reason the lint rule points the way it does: `useTranslations` in a client
component **works**, and silently bills that page 14 kB.
