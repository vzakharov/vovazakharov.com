spectrogram.py measures a song off its four demucs stems, but only a
summary of it survived the run: the text sidecar holds tempo, key,
tuning and per-section chords, while the time series the picture is
drawn from lived only as pixels. Any other visualization of a song
would have had to re-run demucs, whose stems are too big to commit.

A whole-song run writes <slug>.json beside <slug>.png and <slug>.txt:
the tuning, the three best keys, every beat with its chord, the bars,
the sections as the sidecar states them, each drum hit's brightness
per lane, and at a fixed 5 frames a second the loudness envelope and
the melody, harmony and bass strips' pitch-class shares with the
octave carrying each. The spectrogram's own dB map stays in the PNG.
A version field lets a consumer refuse a shape it does not know.

The strip pass and the chord spelling move into numpy-only helpers,
so the picture, the sidecar and the JSON read one set of numbers and
the JSON is tested without matplotlib. All eleven foldered songs are
re-rendered, so each folder describes one demucs run.
