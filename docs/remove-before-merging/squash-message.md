refactor: render page PDFs in CI instead of committing them (pr #78)
```

```
Committed PDFs tied review cost and history weight to the size of the
collection: everything in PRINT_SOURCES re-flags every printable, so a
change to the printed footer rewrote every file, filled the diff with
binaries, and cost a "Viewed" click each.

The render now runs in CI after next build, printing from the static
export into out/, and the repository carries neither the PDFs nor
their manifests. Which server a print comes off is now the script's to
choose — its own dev server, one already running, or the export — so a
render no longer collides with a dev server holding .next/dev/lock,
and pages print concurrently rather than one at a time. Both
publishing lanes render through one composite action over a cache that
falls back to the most recent prior render, so only what drifted is
reprinted.

Printing from the export also closes the gap withDevServer recorded:
a dev server prints what the export prints only while nothing hydrates
visible text. Vet loses its two --check entries, nothing being able to
go stale that is not stored, and a .pdf link answers 404 in a tree
where pnpm content:pdf:<site> has not run.
