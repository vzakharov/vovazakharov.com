```
Every push to main published. Merge being deploy is the point of this
project's setup, but it meant a docs: or chore: merge spent a full
install-build-publish cycle to republish byte-identical output, and put
a deployment in the environment's history that changed nothing.

A gate job now reads the subject lines of the pushed commits and passes
only when one of them is a feat: or a fix:. The build's `if` hangs off
its output and deploy already needs build, so the two skip together and
a filtered push publishes nothing rather than an empty artifact. The
match takes scoped and breaking forms (feat(cv):, fix!:), reads subject
lines only — so a docs: commit whose body mentions fix: does not
qualify — and passes when any commit in the push qualifies, so a feat:
is never stranded behind a docs: commit pushed beside it.

Two consequences for anyone landing work here. The squash subject is
now a production decision rather than a log entry, so a mixed branch
should carry the prefix of what it actually ships. And the filter is
deliberately wrong in one direction: a chore: dependency bump can
change the built output and will not deploy itself. workflow_dispatch
bypasses the gate, so that case is a manual run from the Actions tab.
CLAUDE.md's Deployment section carries both.
```
