```
The project wanted a domain of its own, and the first answer was a
repository of its own. It does not need one: what a second site needs
is its own route tree, its own public/ and its own config, and all
three fit here beside the first.

apps/vova/ and apps/lsa/ hold exactly that, over one shared src/ —
including both sites' page slices, because FSD slices already may not
reach each other sideways, which is the relationship two sites have.
There is no workspace and no task runner: next build <dir> resolves
from the single root node_modules, so an app directory needs only a
config, a route tree and a tsconfig pointing back at src/. Which site
is being built is a build-time constant pinned in each app's config
and parsed on the way in, so an unset value fails the build rather
than serving the wrong site.

CI builds both. vovazakharov.com publishes to its own Pages as
before; the latestageagentic.com build is force-pushed as a single
orphan commit to vzakharov/latestageagentic.com, whose Pages serves a
branch and therefore carries no workflow of its own — which keeps one
pinned toolchain behind both sites instead of handing the second to a
runner nothing here can reach. Rollback is a dispatch from an older
ref, so the receiver never grows a history. CNAME and .nojekyll ride
inside the build, and the publish step refuses an out/ missing
either: a dropped custom domain and a Jekyll-stripped _next/ are both
silent at the far end.

The deploy gate now reads the commit scope it used to discard.
feat(lsa): publishes one site, feat(vova): the other, and an unscoped
feat: or fix: both.
```
