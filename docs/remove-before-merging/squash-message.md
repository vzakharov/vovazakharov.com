```
The site had grown four top-level code directories named after what
their contents are — components/, hooks/, lib/, i18n/ — which says
nothing about what may depend on what. Feature-Sliced Design gives
that an answer, and more usefully gives it to a checker: application
code now lives in src/ under shared/, features/ and pages/, every
slice and shared segment publishes an index.ts, and imports may only
point downward and only through that barrel. Steiger runs the stock
recommended ruleset with an empty override list and eslint-plugin-
boundaries restates the same constraints inline; both were confirmed
to reject an upward import and a barrel sidestep rather than passing
vacuously. vet.sh gains steiger as a fourth concurrent check.

Where things land follows from the rules rather than from taste. The
theme toggle is a feature because both pages use it; the CV's locale
picker and the home page's project and article cards live inside the
page that renders them, because a slice with one consumer is what
Steiger calls insignificant. The app layer is root app/ rather than
src/app: the latter costs two rule overrides, and root app/ already
holds the root layout, the theme provider and the global stylesheet.
Its route files are now thin re-exports of a pages slice. Root pages/
is load-bearing and must stay — Next resolves `pages` as root-pages
or src/pages and then refuses to build when its parent differs from
app/'s, so src/pages needs something at the root to win that lookup.

Locale handling picked up the types it was missing on the way past: a
Locale derived from routing.locales, a toLocale() check narrowing
route params at the boundary, and a message-catalogue map typed
against en.json, so a key added to one translation file and not the
other now fails the type check instead of rendering as a raw key.
.claude/rules/fsd.md carries the enforced conventions and the two
Next.js traps around them; src/README.md is the human tour.

No behaviour changes: the build emits the same five routes, and the
home page and both CV locales were rendered in light and dark and
compared against the pre-change pages.
```
