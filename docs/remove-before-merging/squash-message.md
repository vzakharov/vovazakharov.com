`/issue` and its exporter were declined when this repo adopted the agent
boilerplate, for want of any issue to run them on; the first one retired
that reason. The skill takes an issue end-to-end — export the thread,
split it when the scope demands it, implement, open the draft PR — and
`scripts/export-github-item.py` is the half that matters, since
`gh issue view` does not fetch attachments.

Downloading an attachment takes two accommodations. GitHub redirects a
`user-attachments` URL to a pre-signed S3 URL, and S3 rejects a request
that also carries an `Authorization` header, so the exporter drops that
header when a redirect changes host — a defect every adopter of the
script shares, filed upstream as vzakharov/agent-project-boilerplate#17.
The remote-session egress proxy refuses the same path outright, so a
failed download retries on a direct connection, the accommodation the
session-start hook already makes for `gh`.

The three helpers duplicated between the exporter and `pr-body.py` move
to `scripts/lib/github.py`, filed there as
vzakharov/agent-project-boilerplate#18. `/finalize`'s sweep names the
real exporter, and `pr-body.py` deletes only its own transient body
rather than a directory its sibling's export shares.
