# `/golem` fresh-eyes findings

Plan § "Order" step 7: a subagent that read only `.claude/skills/golem/` and the
skills it points at walked a made-up non-game run ("multi-tenant workspaces in a
web app with a REST API and a React client") through the plan, a bite, a relay,
five drop-ins, one out-of-reach step and one stuck failure. Ranked, most likely
to derail a real run first. Each item is open until a fix commit names it.

1. **Auto-relay is claimed but not built.** `SKILL.md`, `start.md`, `operator.md` say the context-budget hook reads a branch with an operator log as `auto-relay on`; `post-tool-context-budget.sh` only reads `auto-relay/<handle>`. (Being built by the vendored-fix wave — verify it landed.)
2. **The pickup goes through `/go`, which works against the run.** `/relay take` sends a paused plan to `/go` Step 1, whose elephant rules stop after one bite "budget left or not", stop to ask on an unrecommended fork, and run `/pr` at Step 4 (may overwrite the dashboard). `elephant.md` § "A bite" ("one per session … stops there") contradicts `SKILL.md`'s loop step 4. `golem/relay.md` never says what the summary's Next step is, and its pickup steps (install, model check, `pull --no-rebase`) are reachable only after the plan is read.
3. **An operator's change routed through `/task` pulls in the whole planning flow** (`operator.md` § "The intake"): a `.draft.do-not-implement.md`, `/pr`, a hand-off whenever scope is the question; or `/go` Planless with `/polish` and `/pr` mid-bite; a second plan file makes `/go` Step 1 ask which plan. Say "only the plan-or-not judgment, written as a numbered call".
4. **The landing pointer leads nowhere.** `orchestrate.md` § "Worktrees and landing" says the squash mechanics for `wt/<pkg>` are in `templates/brief-common.md`, which only says "commit and push". Nothing on rebasing onto a run branch others push to, landing order, or conflicts.
5. **Scheduled check-ins get logged as operator messages.** The hook logs a `send_later` message (its header says so); `operator.md` says injected prompts are skipped; `orchestrate.md` arms a check-in each wave. A check-in armed before a relay fires into the old session.
6. **The relay depth limit is never defined.** `relay.md` "below the limit" / "at the cap" and the dashboard's `<depth> of <limit>` have no number or source. `get_session` documents neither `lineage` nor effort, yet `SKILL.md`'s model-and-effort check rests on it.
7. **Bite sizing contradicts itself.** `loop.md`/`start.md`: more than two sequential packages is two bites; `orchestrate.md`'s research → spec → step 0 → groups → fixes is four or more. Spec agents sized at "~190k each" are past the 170k subagent notice.
8. **A parked failure collides with "vet green".** Attempt counts disagree: three of different kinds (`SKILL.md`), `/finalize`'s two rounds then ask, "second miss → research agent" (`orchestrate.md`), "script won twice" (`look.md`). A parked gate red has no way to carry into the next bite past `elephant.md`'s vet-green rule.
9. **An out-of-reach step can leave a bite unable to close** — its seeing-means may need the blocked step. Nothing says what the last bite and `/finalize` do with items still on the list, or warns that the "exact command" must not carry a secret's value onto the PR body.
10. **A cut edits only `## Rest of the elephant`**, but a half-built piece sits in `## This bite`, `## Eaten so far`, a `bite-<nn>.md`, `decisions.md`. "Taken out in its own commit" names no one to do it while agents hold the files; a written migration is not undone by deleting code.
11. **Re-steer gaps.** "Standing rules or decisions" — which? Nothing retires a standing rule the re-steer supersedes. The design doc has no path; "its natural stop" contradicts relaying only at the pause. Unclear whether the half-built bite still runs the tail.
12. **The weighing doc has no home**: no path, writer or bite. One thing has three names: "idea docs", `ideas.md`, "weighing doc".
13. **Comments on the plan during the gate have no route in.** No subscription, `golem-log-pr.sh` runs only at a bite's end, and `start.md` covers only chat at the gate.
14. **Working files have no canonical folder.** The hand-over note is a bare `<path>` in `brief-common.md`; briefs and findings files have no named location; `bite-end.md` retires from `docs/remove-before-merging/` while the review brief lives in `docs/plans/<slug>/`. Retiring screenshots is stated in both `operator.md` and `bite-end.md` — home: `bite-end.md`.
15. **Duplicates with `relay/SKILL.md`.** Its Step 3 inherits the model by omitting it; golem passes it — the carve-out belongs in `/relay`. The relay summary's "The conversation" duplicates the operator log and could point at it.
16. **It would not travel to another stack.** `look.md` and `review.md`'s finding classes read as a canvas game's (angles, animated poses, audio, taps, a software renderer). Nothing covers authorization, isolation, migrations or API contracts. `bite-end.md` assumes this repo's dead-export check, the `polish:` floor, squash-subject deploys and the five-percent file.
17. **Journal and ordering.** The journal is a skill file edited on the product branch; the last bite's distill has no order relative to `/finalize`, which sweeps `docs/plans/` and the operator log. `bite-end.md` § "The last bite's leftovers" means the previous bite's. Nobody writes `## Bite 1`, or the heading of a bite started after a relay.
