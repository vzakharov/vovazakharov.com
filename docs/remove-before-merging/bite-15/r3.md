## The API R5's probe reads

`scene.bed.runs.mice()` → `Mice` (`ReadonlyMap<id, count>`);
`scene.bed.runs.runs()` → `MouseRun[]`: `{ from, to, beganAt, course,
start, end, fixed, graphics }` — `graphics.x/y/depth/visible` is the runner
on screen. `house.out(clock)` now includes a run's peek;
`house.mouse.tappedAt` is set only by a tap that peeks (not one that runs,
calls or knocks).

## Decisions taken

- Counts move when a run starts (not its first frame), so two starts in one
  frame never take the same mouse; flee and re-targeted runs take none.
- The outing a run took suppresses that outing's scheduled peek (tap peeks
  still answer), so one head shows at a time.
- A knock opens the door on the tap-peek curve (`peekAfterTap`) with no head.
- The front's stem half width is read at the foot (`stemHalfWidth(genes,0)`),
  its sideways shift is the sill's x on the mushroom; the mushroom's `turn`
  is ignored there.
- A run's mouse looks toward its target (`look` ±1) during its peek leg.
- Runner ink `max(1.5, size·0.01·zoom)`, haze `hazeAhead` at its point,
  lit by the end it is nearer.
- A target that sinks with no view placed: its mouse is counted in at the
  re-target at once. With no door standing it sinks (call 22).
- Field names dodge `type-overlap`: `beganAt` (R2's `startedAt`),
  `Running = { ran, heads, raised }`.
