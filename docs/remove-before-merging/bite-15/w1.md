## Decided where the calls left it open

- **Body length** `WORM_LENGTH` = 4 girths = 0.12 units (a pane and a fifth);
  `WORM_GIRTH` = 0.3 × `PANE` = 0.03 is the drawn thickness (diameter).
- **Out and in slide the whole body**: positions are arc lengths along the
  path and run from `-WORM_LENGTH` (all in the first pane) to
  `length + WORM_LENGTH` (all in the second); `wormBody` leaves out every
  segment outside `[0, length]`, which is how the worm "grows out of" and
  "sinks into" the panes.
- **Inching** is a whole number of inches per crawl (`round(crawl /
INCH_PERIOD)`, so ~0.44–0.47 s each), each "tail catches up, then head
  goes forward" — with the out phase as the first head-forward, the trip
  reads head, tail, head, tail… The body draws in to `1 − 0.35` of its
  length mid-inch. At 0.35 units/s an inch's step (~0.13) is larger than
  the 0.35-body squeeze (0.042), so the "holding" end does not stand still:
  it moves at about a third of the leading end's speed. On a short crawl
  (neighbour, step ≤ squeeze) it truly holds. Neither end ever slips back.
- **The peek** goes straight up `peekPath(slot)` by a body's length,
  unclamped — on a chanterelle (always a lone window) it pokes up past the
  rim over the lip. W4's call if it reads wrong.
- **`girth` is a parameter** of `wormPath` and `wormBody` (default
  `WORM_GIRTH`) so the scene can pass the 5 px floor in units
  (`WORM_GIRTH_LEAST / size`, W2's constant); the path keeps that girth
  plus an ink under `capSurface`.

## Found

- **A chanterelle only ever has one window** (`windowSlots`, its
  `house.test.ts`), so its worm always peeks and the "along the row under
  the rim" path (call 17) is never reached in play. It is built and tested
  on a hypothetical pair at ±2 panes.
- Measured trips: a three-window dome's end-to-end path is ~0.40–0.46 units
  (1.75–1.87 s whole trip), a neighbour ~0.21 (the 1.2 s crawl floor, 1.75 s
  trip); a five-window porcini's end to end ~0.86 (the 3 s ceiling).

## W2's brief — the API

All in the cap's frame (`capFrame`, y up, mushroom-size units), seconds.

```ts
import {
  wormTarget,
  wormPath,
  peekPath,
  pathLength,
  tripDuration,
  wormTrip,
  wormPeek,
  wormBody,
  WORM_GIRTH,
  WORM_PEEK_DURATION,
  WRIGGLE_DURATION,
  type WormTrip,
  type WormPose,
  type WormBody,
} from '../../model/worm';
```

- `wormTarget(slots, count, from, trips): number | undefined` — `slots` =
  `windowSlots(genes)`, `count` = `house.windows.length`, `from` = the
  tapped window's index, `trips` = the house's trip count (increment it per
  trip). `undefined` → peek.
- At the tap, fix the trip: `path = to === undefined ? peekPath(slots[from])
: wormPath(genes, slots[from], slots[to], girth)`, `length =
pathLength(path)`. Never recompute mid-trip (call 8).
- Each frame, `elapsed = time - tappedAt`:
  - trip: `wormTrip(elapsed, length)` → `{ phase: 'out'|'crawl'|'in',
head, tail }` or `undefined` (gone in: stop repainting, the trip is
    over and the next tap starts a new one). `tripDuration(length)` is when.
  - peek: `wormPeek(elapsed, phase?)` → `{ head, tail, look }` or
    `undefined` after `WORM_PEEK_DURATION`; `look` −1…1 turns the head (eye
    left/right), as the mouse's `lookAbout`.
- `wormBody(path, pose, girth, sinceWriggle)` → `{ segments, head }`:
  `segments` are `Circle`s in paint order (tail first, head last), only
  those outside both panes; `head` is the head's circle plus `tangent`
  (radians from the cap's +x, the way the path runs there — for the eye),
  `undefined` while the head is still in a pane. `sinceWriggle` =
  `time - wriggledAt` (omit when none): a sideways swing for
  `WRIGGLE_DURATION` (0.3 s), zero after.
- A tap while `wormTrip`/`wormPeek` is defined is the wriggle (call 20):
  set `wriggledAt`, play `wriggle(0.5)`, leave the trip.
- `girth` for drawing: `max(WORM_GIRTH, WORM_GIRTH_LEAST / size)` in units;
  pass the same to `wormPath` at the tap and to `wormBody`.
- Map the circles through `capFrame(genes)` (and the house's own transform)
  as the windows are; the radii are in mushroom units.
