# Issue #17 — type-overlap: flag repeated base combinations

[Issue #17](https://github.com/vzakharov/vovazakharov.com/issues/17) · export at `docs/issue/17/issue.md`

## Problem

`scripts/type-overlap-check.ts` counts only a type's **own** members; named
constituents of an intersection are inherited, which is what makes `& Base`
clear a finding. One level up, the same _combination_ of bases repeated across
two types is invisible — `Titled & Described` spelled twice is duplication in
exactly the sense a shared member is, and the gate lands green on it.

## Scope

Not split-worthy: one detector, one README, one CLAUDE.md clause. Single PR.

## Approach

Add a **second pairwise pass over named constituent sets**, mirroring the member
pass, sharing its pair→group collapse and its report skeleton.

### 1. Collect constituents alongside members

`walk()` currently pushes a `TypeDecl` only when `members.length > 0`, which
drops a pure combination alias (`type Summarized = Titled & Described`) on the
floor. Widen the condition to `members.length > 0 || bases.length > 0` — a decl
with no own members contributes an empty set to the member pass, so that pass is
unaffected.

Add `namedConstituents(typeNode)`: `[]` unless the alias's type node is an
intersection; otherwise the normalized text of every constituent that is **not**
a type literal (`ts.isTypeLiteralNode` is the own-member case `ownMembers`
already claims). Non-literal covers `Titled`, `Maybe<Foo>`, `Pick<X, 'y'>` — all
genuinely part of the combination — so there is no carve-out to keep in sync
with the member walk. Reuse `normalizeMember`'s whitespace collapse; rename it
to `normalize` since it now serves both passes.

A pure alias participating as a decl is deliberate: it means a type respelling
`Titled & Described` is flagged against the existing `Summarized`, and the fix
the finding names is "use the alias that already exists".

### 2. Threshold

`TYPE_OVERLAP_BASES_MIN`, defaulting to **2**, validated as an integer `>= 2` —
the same shape and the same upward-only override as `TYPE_OVERLAP_MIN`. One
shared base is reuse working as intended and is the end state every member
finding is fixed into, so 2 is the floor, not a starting rung to ratchet down.

### 3. Factor the collapse and the report

The pairwise intersection, the group collapse and the group rendering are
currently top-level statements written once for members. Extract them so both
passes call one copy:

- `type WithShared = { shared: string[] }`, with `Overlap = WithShared & { a; b }`
  and `Group = WithShared & { types }` — the two already share that member, so
  the gate's own floor of 1 requires the base.
- `findOverlaps(select: (d: TypeDecl) => string[], threshold)` → the pairwise
  scan plus the collapse, returning the sorted groups, the pair count and the
  count of types involved.
- `renderSection(...)` → header, group blocks, summary line — parametrized by the
  noun (`members` / `bases`) and by how a shared set renders: members keep one
  `  name: type;` line each, a base combination renders as the single line
  `Titled & Described`, which is the text of the fix.

The `== How to fix ==` tail stays one block. Its steps 2–4 (home rule, no
single-type module, naming families) are already kind-agnostic; step 1 gains a
sub-bullet per kind, emitted only for the kinds that fired:

```
  1. Extract the shared shape as a base type, then have each listed type reuse
     it via intersection:
       - members → `type Foo = SomeBase & { …own members… }`
       - bases   → `type SomeBase = A & B`, then `type Foo = SomeBase & { … }`
```

### 4. Exit code and clean line

Exit 1 when **either** section has findings. The clean line names both floors:
`type-overlap: clean — no shared members (min=1), no repeated base combinations (min=2).`

### 5. Transitivity is out of scope

Constituent identity stays purely syntactic, consistent with the member pass. A
type spelling `Summarized` and one spelling `Titled & Described` share a
combination without sharing a token; resolving the alias graph would catch it
and is a separate change. It becomes a named gap in README §8 rather than
silence.

script's own `TypeDecl`, and no pair of them shares two.

## DRY notes

- **Genuinely shared, extracted:** the pair→group collapse and the report
  rendering. Both passes produce pairs of `TypeDecl` carrying a `string[]` of
  shared entries, so one `findOverlaps` + one `renderSection` serve both — this
  is the factoring the issue asks for, and duplicating the collapse would give
  the two passes independently drifting output formats.
- **Reused, not re-declared:** `normalizeMember` (renamed `normalize`) already
  does the whitespace collapse the constituent pass needs; `WithShared` is the
  shared base `Overlap` and `Group` both require once `Group`'s member list
  stops being members-specific.
- **Deliberately not extracted:** the two _selectors_ (`ownMembers`,
  `namedConstituents`) stay separate functions rather than one parametrized
  walker. They read the same `ts.TypeNode` but ask opposite questions of each
  constituent, and a single function with a "which half do you want" flag would
  be longer and less legible than two that each state their own rule.
- **Deliberately not extracted:** the threshold parsing runs twice, six lines
  apart, for two env vars with different floors. A `readThreshold(name, floor)`
  helper is the obvious extraction and is worth doing; it stays a small local
  function rather than moving to `lib/`, since nothing outside this script reads
  env-var thresholds.
- No new module: the script lands around 330 lines, under CLAUDE.md's ~450
  guideline, and README §6's "don't mint a file per base" applies to the shared
  types it adds.
