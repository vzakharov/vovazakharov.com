## API

`@/island/entities/terrain/tile` (`model/cube-tile.ts`). The key is `CubeCell`
from `@/island/shared/globe` itself: a `CubeTileKey = CubeCell` alias is
rejected by `vova/no-redundant-type-alias`.

```ts
const CUBE_MAX_LEVEL = 17;  // ≤ ~1.19 m spacing (65-vertex grid)
const CUBE_MIN_LEVEL = 2;   // 6 × 16 = 96 roots
function cubeTileId(key: CubeCell): string;            // `${face}/${level}/${x}/${y}`
function faceLattice(level: number, cells: number, k: number): number;
  // face coordinate 2k/(2^level·cells) − 1, exact; edges land on ±1
function tileHolds(key: CubeCell, point: FacePoint): boolean;  // edges included
type TileCap = { centre: Vec3; radius: number; border: readonly Vec3[] };
  // unit centre, angular radius, 8 unit border points (4 corners, then 4 edge midpoints)
function tileCap(key: CubeCell): TileCap;
function capGap(cap: TileCap, direction: Vec3): number;   // radians, 0 inside
function capsApart(a: TileCap, b: TileCap): number;       // radians, 0 where they meet
function cubeTileSide(key: CubeCell): number;
  // metres: longest cell edge in the tile × cells; ∈ [2√2/3, 1] × R·π/2^(level+1)
```

`TILE_GRID`, `SPLIT_RATIO` are shared with the planar modules.

`@/island/entities/terrain/quadtree`:

```ts
type CoastDistance = (direction: Vec3) => number;   // signed metres to the coast
type CubeSelectOptions = Framed & { coast?: CoastDistance; ground?: (direction: Vec3) => number };
function selectCubeTiles(eye: Vec3, options?: CubeSelectOptions): CubeCell[];
  // eye in world metres; sorted level, FACES order, y, x; balanced across faces
function cubeSplitRule(eye: Vec3, coast?: CoastDistance): (key: CubeCell) => boolean;
function cubeDetailCut(eye: Vec3, coast?: CoastDistance): (p: Vec3) => number;  // p a unit direction
```

`Framed = { frustum?: Frustum }` now lives in `view.ts`; the planar
`SelectOptions` builds on it too (type-overlap).

## Decisions

- **Lattice for B4**: lattice point `(i, j)` of a tile is
  `faceToSphere(face, faceLattice(level, CELLS, x·CELLS + i), faceLattice(level, CELLS, y·CELLS + j))`;
  tested bit-equal across face edges on six sample tiles, level 2 to 17.
- **`cubeTileSide`** is analytic: along a constant-`v` line the equal-angle map
  moves `(π/4)(1+s²)√(1+t²)/(1+s²+t²)` radians per unit `u` (`s = tan πu/4`,
  `t = tan πv/4`), largest at the span's largest `|u|` and smallest `|v|`. Brute
  force: within 1 % of the longest cell edge and never under it.
- **Split distance**: the cap's nearest point at the eye's clamped height,
  `√((|e|−ρ)² + 4|e|ρ sin²(θ/2))`, θ = `capGap`.
- **`cubeDetailCut`'s neighbourhood** is the cells within two `neighbour` steps
  of each ancestor (diagonals through either order, so a cube corner is
  covered), and it includes same-level leaves as well as coarser ones:
  `cubeTileSide` differs with position, so a same-level neighbour can ask more.
  The floor is level 17's twice-spacing at a face centre (the widest).
- `balance` stays internal (`balanceCube`), as the planar one is.

## Numbers

- `selectCubeTiles` with the disc coast, eye at 2 m–10 km over the centre, a
  face edge, a cube corner, both poles, a face middle: 180–452 tiles, 2–12 ms
  each in Node.
- `cubeDetailCut` 1 mm across the `px`/`nz` edge, 2001 places along it: worst
  relative difference 1.1e-7 (eye 2 m and 100 m), 5.1e-8 (10 km), 1.1e-9 (1 000
  km); absolute ≤ 2.8e-5 m. The ramp's own slope is `4/CELLS` per metre, so
  under the eye at 2 m a 1 mm pair may differ by up to ~2.6e-5 relative with no
  discontinuity: the test there checks that slope bound on 2001 pairs within
  0.002 face units of the eye; the < 1e-6 test runs from 10 km and 1 000 km.
- Nadir: the cut under the eye is ≥ the nadir tile's twice-spacing and ≤ 2× it
  (the planar test's equality loosens because a coarser neighbour's cap reaches
  a little past its tile, as `b3-map.md` § 2.4 accepts).
- Suite (tile + quadtree, planar included): 127 tests, under 1 s.
