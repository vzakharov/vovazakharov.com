# A LinkedIn content plan mined from the Playgram case study

## The goal, stated plainly

A standing backlog of **small, self-contained LinkedIn posts**, each built on one concrete piece of work, mostly from the Playgram case study and later from whatever else ships. Every post has to leave a practitioner with something they can use on Monday. Nothing is a teaser for a longer thing; a post that only works as an advertisement is not a post.

Two effects are wanted and **neither is ever named in the text**: that a reader who needs this kind of work done starts wondering who does it, and that the name becomes one people recognise on the subject of running coding agents at scale. Both come from the writing being useful and specific, not from a closing line asking for anything. No CTA, no "what's your experience?", no "DM me". The dots stay for the reader to connect.

## What this change delivers

1. **`writing/linkedin/plan.md`** — the content plan: the post inventory, the recurring post shapes, the sequencing, and the form constraints.
2. **`writing/linkedin/drafts/case-study-announcement.md`** — the calibration draft: the post that carries the case-study PDF as an attachment.
3. **A `writing/` row in CLAUDE.md's repository-layout table.**

Prose only. Nothing here touches `src/`, `scripts/` or `public/`, so vet has nothing new to check and the squash subject is a `docs:` — which does not spend a deploy.

**Deliberately not in this change:** the anti-slop writing rules. They get written against a marked-up draft rather than anticipated. The plan provisions their home — `.claude/rules/writing.md`, path-scoped to `writing/**` so they load whenever a draft is touched — and seeds it with the two conventions already stated out loud (below), nothing more.

## Where the files live

**`writing/linkedin/` at the repo root.** Not `public/content/`, which is served publicly — unposted drafts crawlable before they run on LinkedIn is the wrong order of operations. Not `docs/`, whose every known subdirectory (`plans/`, `issue/`, `pr/`, `remove-before-merging/`) is a working artifact `/finalize` sweeps before merge, so a durable asset there is a trap set for the next agent pattern-matching on its neighbours. `writing/` costs one row in the layout table and generalises when the next channel arrives.

```
writing/
  linkedin/
    plan.md              # the backlog, the shapes, the form
    drafts/
      <slug>.md          # one file per post
```

Each draft carries frontmatter: `source` (the case-study section its facts come from), `shape`, `status` (`draft` | `approved` | `posted`), `posted` once it is, and `blocked-on` while something outside the draft has to land first.

## The attachment, and the branch that owns it

The first post's attachment is the case study as a PDF. Attaching one on LinkedIn reads differently from linking: it opens in the feed, it flips locally, it does not ask the reader to leave.

**That pipeline is not this change's to build.** `claude/content-url-suffixes-j2qjau` already carries it, further along and better factored than a plan written here would have got it: `scripts/render-pdf.ts` behind `pnpm content:pdf`, a `--check` mode in vet, the staleness skeleton lifted into `scripts/lib/render-manifest.ts` with `render-og.ts` moved onto it, and provenance printed by the article footer rather than by Chrome — whose own footer names whatever host did the render and cannot be overridden from the CLI. The renders are committed there already, cuts included.

So this plan takes the artifact as a given and records only what it needs to know about it:

| | |
| --- | --- |
| **File** | `public/case-studies/playgram.pdf` |
| **URL** | `/case-studies/playgram.pdf` |
| **Cuts** | `playgram.mini.pdf`, `playgram.nano.pdf`, same rule |
| **Regenerated by** | `pnpm content:pdf` |
| **Available from** | the merge of `claude/content-url-suffixes-j2qjau` |

Note the path: that branch moves the content tree up a level, so `public/content/` stops existing. Anything written here names the post-move path, never the current one.

## Merge-time coordination

Two things need hands when these branches land, and **either session does whichever is still outstanding when it gets there** — there is no required order.

1. **CLAUDE.md's repository-layout table is edited by both.** This branch adds a `writing/` row; the other rewrites the `public/` row to name the collection directories. A textual conflict in one table, resolved by keeping both edits. Nothing subtler than that is at stake.
2. **The announcement post cannot go out before the PDF exists on `main`.** If this branch lands first, `writing/linkedin/` describes an attachment the trunk does not yet have — which is fine on disk and not fine on LinkedIn. The draft carries a `blocked-on: claude/content-url-suffixes-j2qjau` frontmatter key that is cleared once that branch merges, and `plan.md` states the dependency in prose so it survives someone reading only the plan.

Nothing else overlaps: `writing/` is a new tree, and the other branch touches `public/`, `src/`, `scripts/` and `.claude/rules/content.md`, none of which this one goes near.

## The calibration draft

The first post announces the case study and attaches the PDF. The operator supplied the opening almost whole, and **it is a voice specimen, not a first pass** — it does not get tightened, rebalanced, or improved. The two ellipses get filled and nothing else moves:

> So from March to August this year I was doing quite a fun thing -- well, fun if you're the weird kind who loves dabbling with parsings, abstractions and ... Once done, I thought, why not write a case study about it. I only went halfway and it's already a 40-minute read 🙈 Not really thinking anyone would seriously read it all -- but maybe skim through? There's some interesting stuff on ..., ..., and managing a team of 15+ agents at a time.

The three blanks are the only open drafting decisions, and each wants something concrete from the case study rather than a category:

- **the first** completes "parsings, abstractions and …" and should land on the strangest concrete object in the project — the 11.6 MB minified JSON that was the app's entire source, or the 3,487 files it got cut into;
- **the second and third** are the skim bait, and should name specifics that reward opening the file rather than topic labels: the lint rule whose failure mode was an authentication hole, the two type shapes that both compiled while logging zeroes for months, the migration numbered `0099` on a branch that had not merged `0098`.

No link, since the PDF is right there. No sign-off line.

**One caveat worth stating rather than discovering:** this post is an announcement, so the rules it calibrates will cover the personal register and say nothing about the teaching register the other eighteen posts live in. Post #3 below, the type-overlap gate, is the natural second calibration draft once the first round of rules exists — not in this change.

## Form

- **1,000 characters, hard ceiling.** Long enough for one idea completely; short enough to be read whole.
- **The first two lines carry it.** LinkedIn folds at roughly 200 characters, so the opening states the concrete thing rather than promising it. No "I want to share some thoughts on…", no question-as-opener.
- **`--`, never `—`.** Written as two hyphens on purpose: enough readers now treat an em dash as a machine's fingerprint that the correct punctuation has become the wrong signal. This is the first entry for `.claude/rules/writing.md`.
- **Emoji: sparingly, and only self-deprecating.** One 🙈 doing real work is in the voice; emoji as decoration, as bullet markers, or as enthusiasm is not. Text emoticons — `;-)` — are in the voice too.
- **One idea per post.** A second good idea is a second post.
- **No single-sentence-per-line staccato**, which is the house style of the genre and reads as the genre rather than as a person.
- **Numbers stay unrounded.** 3,487 files, 11.6 MB, 8,123 imports. The precision is the evidence.
- **English only.** The site is bilingual; this isn't.

## Linking back

Left open on purpose. The first post carries a PDF and needs no link at all, and whether later posts point anywhere is a question the first few answers will settle better than a rule written now.

## Sequencing

Free-standing and unnumbered — a numbered series makes every post after the first look like homework and makes a missed week visible. `plan.md` carries a suggested opening run, not a schedule: the announcement, then **1 → 3 → 12 → 5 → 2** below, which opens on the strangest artifact, follows with a bug that cost real money, then the handover — the one that most plainly answers "so did it work?" — before settling into practitioner material.

## The five shapes

Naming the shapes is what stops eighteen posts from being eighteen variations of one paragraph, and gives the future writing rules something concrete to constrain. The announcement post above belongs to none of them — a one-off does not need a category invented for it.

- **Footgun** — a specific bug, why it was invisible, and the thing that catches it now. Ends on the mechanism, never on a moral.
- **Measurement** — a number nobody else has, and what it does and doesn't mean. Must include the deflating half; a measurement that only flatters is an ad.
- **Reversal** — a received best practice that is wrong in a named context, with the reason it's usually right left standing.
- **Receipt** — an unflattering fact about my own work, scored. It does the most for credibility, and must never be false modesty about something that actually went well.
- **Artifact** — a small piece of real code, config or output, shown and then explained. The reader should be able to steal it.

Rough mix over any ten posts: 3 footgun, 2 measurement, 2 reversal, 2 receipt, 1 artifact. Receipts are the scarce ingredient — overused they turn into a bit.

## DRY notes

- **The case study is the single source of truth for every fact**, and posts have to restate those facts rather than reference them — a LinkedIn reader has nothing open. Duplication by necessity, so the mitigation is a pointer, not an extraction: each draft's `source` frontmatter names the case-study section it draws from, making "which posts repeat this number?" a grep instead of a memory. No script, no gate — a checker over eighteen prose files would cost more than the drift it prevents.
- **The PDF pipeline is depended on, not rebuilt.** It is the largest thing this change could have duplicated: a second renderer would have carried its own manifest, staleness check and Chromium invocation, and diverged on the detail that matters most — which host the footer names. `claude/content-url-suffixes-j2qjau` owns all of it.
- **The five shapes are defined once, in `plan.md`.** Drafts name a shape in frontmatter and never restate its definition.
- **No post template, deliberately.** The obvious extraction — an opener slot, a body slot, a closer slot — is exactly the mechanism that produces the interchangeable voice this exercise exists to avoid. The five shapes are as much structure as is safe.
- **Nothing here touches `src/`, `scripts/` or `public/`**, so no FSD, type-overlap or styling surface is involved.

## Risks worth naming

- **The plan is only as good as the draft.** If the calibration draft comes back as slop, the inventory survives — the shapes and the facts are independent of it — but the writing rules become the load-bearing artifact and the backlog waits on them.
- **The dependency is on a branch, not on `main`.** If `claude/content-url-suffixes-j2qjau` changes shape before it lands — a different filename, a different route — the two lines in this plan that name the artifact are what go stale. They are deliberately confined to one table for that reason.
- **The PDF fails quietly, and this change cannot check it.** A print rendering goes wrong by producing something ugly rather than by failing a gate, so somebody opens the file and looks at it before the post goes out. That verification belongs to the other branch's QA checklist; this one only depends on its outcome.
- **Eighteen posts is a lot of surface for one case study.** Around post ten the material thins and the backlog needs Part II, or new work, to continue. Better named now than discovered in November.
