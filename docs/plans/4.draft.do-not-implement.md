# Issue #4 — Playgram case study, Part I

## What this is

Vova spent March–August 2026 rebuilding **Playgram** — a live, feature-rich AI chat product — from a Bubble no-code app into a Next.js codebase, working almost entirely through parallel Claude Code agents. He wants that written up as a long-form, first-person case study: partly a war story, partly a field manual for agent-driven development, and — unstated but always in mind — a portfolio piece whose real message is *hire this guy*.

Issue [#4](https://github.com/vzakharov/vovazakharov.com/issues/4) is his own ~5,300-word brief for it. It is not a spec to implement but a **draft in note form**: his prose, his structure, his verdicts, with roughly twenty bracketed placeholders where he has asked the agent to go find the real thing — commit counts, file counts, code excerpts, diagrams, supporting links. The job is to hydrate that brief into a finished document in his voice: keep his wording (some of it verbatim by request), fill every placeholder with researched fact, and improve the structure where storytelling calls for it.

He capped it at "Part I" because the brief outgrew a single article. Part II is already sketched at the end of the brief and is **out of scope here**.

**What this plan produces:** three Markdown files — the full case study and two shorter cuts of it — plus one generated chart. No web page, no PDF, no route: the issue explicitly defers those to a follow-up.

## Structure

The brief invites a better structure. Six changes; everything else keeps the brief's order and wording:

1. **Result before apology.** A short numbers strip opens the document (4 months · 11 MB of JSON · 1,537 commits · 1,063 merged PRs · multi-second → sub-second cold loads · 4 releases and 3 cutovers), *then* the pre-intro. A reader deciding whether to spend half an hour needs the payoff first, and the unspoken CTA is served better by numbers than by an apology for length.
2. **Timeline promoted out of "How".** "The four months, in numbers" becomes its own top-level section between "what" and "How" — it frames everything that follows rather than being the first phase of it.
3. **"How" gets two named arcs** instead of a flat list of six subsections:
   - **Setting the table** — the split · the decision docs · the strutwork · planning. Everything before the code could scale.
   - **Learning to run twenty agents** — cloud VMs · the skills · `/plan` and `/implement` · context hygiene.
   This gives the reader a spine ("first I built the guardrails, then I learned to scale") and makes the mini version nearly fall out of the section headings.
4. **"Session-based development" is renamed "Context hygiene"** — the operator picked it. The section's own rule, *one session, one thread*, becomes the memorable line inside it and one of the quote callouts, so the heading names the discipline and the callout names the practice.
5. **Every subsection carries a `Verdict: X/10`.** The recurring device is what makes the piece read as an honest retrospective rather than a brag sheet. Five verdicts already exist in the brief (the split 10/10 · the decision docs 6.5/10 · FSD 8.5/10 · linting 10/10 · planning 6/10). **Four subsections lack one, all of them under "Execution (with agents)": Cloud-based agent VMs · Building the skills · Planning and implementing · Context hygiene.** The operator is supplying those four numbers. Until they arrive, write each verdict line as `Verdict: <!-- TODO(vova): score -->` followed by the one-clause justification drafted in his voice, so the sentence is ready and only the digit is missing.
6. **`## To be continued`** stays verbatim as the Part II tease.

### Quote callouts

Eight `>` callouts, each repeating a line that already appeared in the running text, per the brief. **A callout must stand on its own.** Pulled out of the paragraph that set it up, a bare line like "But boy could I be wronger" tells a skimmer nothing — and skimmers are exactly who callouts are for. So every callout is made self-contained by one of two means, whichever is less intrusive: fold the missing subject into the line itself, or give it a short italic label above it naming what it is about. Never both, and never a label that just repeats the line.

## Scope boundaries

**Part II's territory stays in Part II.** The brief's closing section already lists what is deferred, and data migration is one of its named items. For Part I that exclusion is absolute rather than a matter of depth: do not describe, quote, link, screenshot, name a path for, or characterise **how migration inputs or outputs were stored, staged, tracked or moved** — not in the body, not in an aside, not in a code excerpt, not in the mini or micro cuts. Where the narrative genuinely needs to acknowledge the problem existed, the brief's own framing is the ceiling and the floor: the app kept its data in Bubble's proprietary format with no easy migration path, and solving that is a Part II story. Nothing beyond that sentence.

This is stricter than the rest of the piece and it is deliberate, so treat any pull toward explaining the mechanics as the signal to stop. If a specific sentence feels borderline, ask the operator before writing it — and ask by pointing at the sentence, not by restating the mechanics in the question.

**Other exclusions:** workspace names, customer names, user data, secrets, environment values, and internal hostnames beyond what the issue's own attachments already show.

**In scope:** file and directory paths, release version numbers and dates, commit and PR counts, `docs/decisions/` filenames, lint-rule names, skill names and descriptions, and short illustrative excerpts (a split fragment, a lint-rule message, a plan excerpt). Playgram management approved the disclosures; the brief records that, and the case study repeats it as a disclaimer.

**Private-repo references never become hyperlinks.** The brief links `Playgramai/playgramapp` PR #2006, but that was shorthand for the agent's benefit — the repo is private, so any such link 404s for every reader. Cite work of that kind **descriptively** instead ("a 75-commit, 139-file PR we had to ship mid-production"), with no URL and no bare `#number`, which reads as a link that failed. Links to `vzakharov/agent-project-boilerplate`, `anthropics/claude-code`, this repo, and public third parties are fine and wanted.

**One thing the recording shows, decided rather than overlooked:** the intro screen capture is from a dev environment and displays `playgram-app-dev.up.railway.app` and the personal test workspace "Los Vovas 2". ## DRY notes

- **The three cuts are the one real duplication risk, and the duplication is intentional.** Mini and micro restate the full document's claims by definition. Factoring shared sentences into an include would be net-negative twice over: there is no build step to expand includes (this is a static export, and the files are meant to be readable as-is on GitHub), and each length wants *different* phrasing, not the same phrasing truncated — a shared fragment would force one register onto three audiences. Kept as three independent documents. The counterpart obligation is that the **numbers** must not drift between them, which the confirmed-numbers table above exists to prevent: every figure traces to one row of it.
- **Numbers live in exactly one place per artifact.** The chart's underlying series is committed as CSV and the SVG is generated from it, so the chart and the prose cannot disagree; the prose cites the same CSV-derived totals.
- **Nothing is extracted into a shared helper**, because there is no code here. No component, no lib module, no script is added — the SVG is a committed artifact, not a build step, so there is no generator to keep alive and no dependency to justify. A one-off generation script, if one is written, goes in `tmp/` and is not committed.
- **`lib/metadata.ts` and the existing site code are untouched.** The follow-up issue that renders these as a page will reuse them; doing it now would be building for a requirement this issue explicitly excludes.
- **The research clone is not vendored.** No part of the Playgram repo is copied into this one beyond the short quoted excerpts the document actually displays.
