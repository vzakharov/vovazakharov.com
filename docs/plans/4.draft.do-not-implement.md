## Structure

The brief invites a better structure. Six changes, everything else kept in the brief's order and wording:

1. **Result before apology.** A short numbers strip opens the document (4 months · 11 MB of JSON · 1,537 commits · 1,063 merged PRs · multi-second → sub-second cold loads · 4 releases and 3 cutovers), *then* the pre-intro. A reader deciding whether to spend 30 minutes needs the payoff first, and the unspoken CTA is served better by numbers than by an apology for length.
2. **Timeline promoted out of "How".** "The four months, in numbers" becomes its own top-level section between "what" and "How" — it frames everything that follows rather than being the first phase of it.
3. **"How" gets two named arcs** instead of a flat list of six subsections:
   - **Setting the table** — the split · the decision docs · the strutwork · planning. Everything before the code could scale.
   - **Learning to run twenty agents** — cloud VMs · the skills · `/plan` and `/implement` · one session, one thread.
   This gives the reader a spine ("first I built the guardrails, then I learned to scale") and makes the mini version almost fall out of the section headings.
4. **"Session-based development" is renamed "One session, one thread"** — it names the actual rule, it is memorable, and it survives being quoted as a callout. (Runners-up considered and dropped: "Disposable sessions", "The plan is the handoff", "Context hygiene".)
5. **Every subsection keeps its `Verdict: X/10`**, and the two that lack one in the brief get one, because the recurring device is what makes the piece read as an honest retrospective rather than a brag sheet.
6. **`## To be continued`** stays verbatim as the Part II tease.

## DRY notes

- **The four cuts are the one real duplication risk, and the duplication is intentional.** Mini, micro and nano restate the full document's claims by definition. Factoring shared sentences into an include would be net-negative twice over: there is no build step to expand includes (this is a static export, and the files are meant to be readable as-is on GitHub), and each length wants *different* phrasing, not the same phrasing truncated — a shared fragment would force one register onto four audiences. Kept as four independent documents. The counterpart obligation is that the **numbers** must not drift between them, which the confirmed-numbers table above exists to prevent: every figure traces to one row of it.
- **Numbers live in exactly one place per artifact.** The chart's underlying series is committed as CSV and the SVG is generated from it, so the chart and the prose cannot disagree; the prose cites the same CSV-derived totals.
- **Nothing is extracted into a shared helper**, because there is no code here. No component, no lib module, no script is added — the SVG is a committed artifact, not a build step, so there is no generator to keep alive and no dependency to justify. A one-off generation script, if one is written, goes in `tmp/` and is not committed.
- **`lib/metadata.ts` and the existing site code are untouched.** The follow-up issue that renders these as a page will reuse them; doing it now would be building for a requirement this issue explicitly excludes.
- **The research clone is not vendored.** No part of the Playgram repo is copied into this one beyond the short quoted excerpts the document actually displays.
